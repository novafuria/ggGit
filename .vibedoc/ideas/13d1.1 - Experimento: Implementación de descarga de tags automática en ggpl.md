# [EXPERIMENTO] - Implementación de descarga de tags automática en ggpl

## 🎯 Objetivo

Modificar el flujo del comando `ggpl` (y opcionalmente la interfaz `GitInterface` en `src/core/git.py`) para que la operación de pull descargue y actualice de manera automática todas las etiquetas (tags) del servidor remoto, validando su comportamiento mediante pruebas automatizadas.

## 🌎 Contexto

Los tags son fundamentales para la orquestación de lanzamientos. Este experimento valida de manera práctica la hipótesis [[13d1 - Hipótesis: Sincronización automática de etiquetas en comando pull]] para enriquecer la funcionalidad de `ggpl` y mantener la consistencia sin requerir intervención manual del usuario.

## 💡 Diseño Experimental

1. **Refactorización Técnica**:
   - Modificar el método `pull` en `src/core/git.py` para aceptar un booleano opcional `fetch_tags=True`.
   - Si `fetch_tags` es verdadero, el método debe ejecutar `git pull` y luego ejecutar `git fetch --tags` (o usar la opción `--tags` si es compatible de forma limpia con la firma del comando).
   - Asegurar que `ggpl.py` aproveche esta nueva capacidad por defecto.
2. **Fase de Validación**:
   - Escribir una prueba de integración en `tests/test_git_interface_extended.py` (o similar) que simule un repositorio local y un remoto simulado que contenga nuevos tags.
   - Ejecutar `ggpl` y verificar que los tags remotos aparezcan en el repositorio local.
3. **Métrica de éxito**: Al correr `ggpl` en un repositorio desalineado de tags, el comando finaliza con código de salida `0` y `git tag` local muestra todos los tags remotos actualizados.

## 📦 Artefactos Esperados

- 📦 **Método GitInterface Actualizado**: Modificación en `src/core/git.py`.
- 📦 **Comando ggpl Actualizado**: Modificación en `src/commands/ggpl.py`.
- 📦 **Pruebas de Integración de Tags**: Nuevos casos de prueba en `tests/test_git_utility_commands.py` o similar.

## 🔍 Criterios de Éxito

### Sincronización de Tags Exitosa:
- Dado que el repositorio remoto contiene etiquetas que no existen en el clon local
- Cuando se ejecute el comando `ggpl`
- Entonces el comando debe finalizar con éxito (código de salida `0`) y las etiquetas remotas deben aparecer listadas localmente al ejecutar `git tag`.

### Resiliencia sin Tags:
- Dado que el remoto no tiene etiquetas configuradas
- Cuando se ejecute el comando `ggpl`
- Entonces la operación de pull debe completarse con éxito de forma estándar sin fallar ni emitir advertencias de error.
